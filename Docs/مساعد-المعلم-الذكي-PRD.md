# PRD – مساعد المعلم الذكي (AI Teacher Assistant)

## 1. نظرة عامة

| | |
|---|---|
| **اسم الميزة** | AI Teacher Assistant |
| **الهدف** | توفير مساعد ذكي داخل منصة المدرسة يساعد المعلمين على إنتاج جميع المستندات التعليمية خلال ثوانٍ، مع الالتزام بسياسات المدرسة والمنهج المستخدم، دون الحاجة إلى كتابة برومبتات معقدة. |

---

## 2. المشكلة

يعاني المعلم من:

- استهلاك وقت كبير في إعداد الخطط
- صعوبة كتابة الأهداف ونواتج التعلم
- تكرار الأعمال الروتينية
- اختلاف جودة الخطط بين المعلمين
- عدم معرفة كيفية كتابة Prompt احترافي

---

## 3. الحل

إضافة مساعد ذكي داخل المنصة يقوم بـ:

- إنشاء الخطط
- إنشاء مخطط الدرس
- إنشاء الأنشطة
- إنشاء الاختبارات
- إنشاء أوراق العمل
- إنشاء الرسائل
- إنشاء التقارير

كل ذلك اعتمادًا على بيانات الطالب والمعلم والمنهج الموجودة داخل النظام.

# PRD – نظام رصيد الذكاء الاصطناعي (AI Credits System)

| | |
|---|---|
| **الإصدار** | 1.0 |
| **الحالة** | Ready for Development |

---

## 1. الهدف

إنشاء نظام لإدارة استخدام الذكاء الاصطناعي داخل منصة المدرسة يمنع الاستهلاك المفرط، ويحافظ على الميزانية الشهرية، مع توفير تجربة عادلة لجميع المعلمين.

بدلاً من تحديد عدد الطلبات، يعتمد النظام على رصيد (Credits) يتم خصمه حسب نوع العملية وحجمها.

---

## 2. المشكلة

إذا تُرك الذكاء الاصطناعي بدون قيود فقد يحدث الآتي:

- معلم يطلب اختبارًا من 100 سؤال
- معلم يحلل كتابًا كاملاً
- معلم يعيد التوليد عشرات المرات

وهذا قد يستهلك الميزانية بالكامل خلال أيام.

---

## 3. الحل

- كل معلم يمتلك رصيدًا شهريًا
- كل عملية ذكاء اصطناعي تستهلك عددًا معينًا من النقاط

إذا انتهى الرصيد:

- يتوقف التوليد
- تظهر رسالة توضح انتهاء الرصيد
- يستطيع مدير المدرسة زيادة الرصيد يدويًا

---

## 4. المستخدمون

- Teacher
- Head of Department
- School Manager
- Admin

---

## 5. أنواع الرصيد

### الرصيد الشهري

يعاد تلقائيًا أول كل شهر.

**مثال:** 100 نقطة

### الرصيد الإضافي

يمكن للمدير إضافته يدويًا.

**مثال:** +50 نقطة

### الرصيد المستهلك

يحسب تلقائيًا.

### الرصيد المتبقي

```text
الرصيد الحالي = الشهري + الإضافي − المستهلك
```

## 7. قواعد الخصم

- لا يتم خصم أي نقاط إلا إذا نجحت عملية التوليد
- إذا فشل الاتصال أو حدث خطأ في مزود الذكاء الاصطناعي، لا يتم الخصم
- إذا ألغى المستخدم الطلب قبل الإرسال، لا يتم الخصم

- أكثر المواد استخدامًا

## 13. التنبيهات

| نسبة الاستهلاك | الإجراء |
|---|---|
| 80% | تنبيه أصفر |
| 90% | تنبيه برتقالي |
| 100% | تنبيه أحمر مع إيقاف التوليد |

---

## 14. شاشة انتهاء الرصيد

يعرض النظام:

> انتهى رصيد الذكاء الاصطناعي لهذا الشهر.
> يرجى التواصل مع مدير المدرسة للحصول على رصيد إضافي.

---

## 15. الإعدادات

داخل لوحة الإدارة:

| الإعداد | القيمة |
|---|---|
| الرصيد الشهري | 100 نقطة |
| إعادة التعيين | شهري / يدوي |
| السماح برصيد إضافي | نعم / لا |
| السماح بإعادة التوليد | نعم / لا |
| الحد الأقصى للعملية الواحدة | مثلاً 30 نقطة |

## 17. واجهات API

#### `GET /credits`

عرض الرصيد الحالي.

#### `GET /credits/history`

عرض السجل.

#### `POST /credits/check`

التحقق من وجود رصيد قبل تنفيذ العملية.

#### `POST /credits/deduct`

خصم النقاط بعد نجاح العملية.

#### `POST /credits/add`

إضافة رصيد بواسطة المدير.

#### `POST /credits/reset`

إعادة تعيين الرصيد الشهري.

---

## 18. قواعد العمل (Business Rules)

- لا يُسمح بتنفيذ أي عملية بدون رصيد كافٍ
- الخصم يتم بعد نجاح الاستجابة فقط
- العمليات الفاشلة لا تُخصم
- المدير فقط يستطيع تعديل الرصيد
- جميع عمليات الخصم والإضافة تُسجل في سجل دائم لا يمكن حذفه

---

## 19. متطلبات مستقبلية (Future Enhancements)

- احتساب النقاط تلقائيًا بناءً على عدد الـ Tokens بدلًا من جدول ثابت
- دعم أكثر من مزود ذكاء اصطناعي مع اختلاف تكلفة كل مزود
- تخصيص رصيد مختلف حسب دور المستخدم (معلم، رئيس قسم، مدير)
- إمكانية ترحيل نسبة من الرصيد غير المستخدم إلى الشهر التالي
- لوحة تحليل تكلفة الذكاء الاصطناعي لكل مادة وكل قسم
