## 1) ما هذه القاعدة؟

**اسم المنصة الظاهر:** أولمبياد النخبة 1448 هـ  
**الشعار:** نحو القمة بالتميز  
**النطاق النموذجي للموقع:** حسب إعداد المدرسة (مثال placeholder: `https://YOUR_SCHOOL_DOMAIN`)

## 3) تعريف المنصة باختصار

منصة ويب مدرسية (مدرسة واحدة — ليست متجراً عاماً متعدد المدارس) تجمع:

1. **نظام نقاط الأولمبياد** وتحفيز الطلاب والفصول.
2. **الشؤون الأكاديمية** (واجبات، خطط أسبوعية، جداول، مراجعات).
3. **اختبارات إلكترونية** وبنك أسئلة وتحليلات.
4. **بوابات الطالب وولي الأمر**.
5. **مساعد ذكاء اصطناعي للمعلمين** (توليد محتوى تعليمي).
6. **مسابقة يومية بين الفصول** (حسب تفعيل المدرسة).
7. **دعم فني داخل المنصة** عبر صفحة الدعم.
8. **إشعارات وتذكيرات** (بما فيها واتساب حسب إعداد الإدارة).

الأدوار الشائعة: طالب، ولي أمر، معلم، مشرف، وكيل، رائد نشاط، مدير مدرسة، مطور منصة.

## 4) كيف تستخدم هذه الملفات؟

### أ) بناء PDF/HTML/ZIP تلقائياً

```bash
npm install
npm run build-docs
```

المخرجات: `dist/html/` · `dist/pdf/` · `Olympiad-Knowledge-Base.zip` · `dist/pdf/KnowledgeBase.pdf`  
التفاصيل: `build/README.md`

### ب) رفع إلى Meta Business AI / WhatsApp
1. ارفع الملفات كمصدر معرفة للبوت.
2. اجعل `AI_AGENT_CONTEXT.md` أولوية قصوى في التعليمات النظامية.
3. اربط `CONTACT.md` و`SUPPORT.md` و`FAQ.md` كمرجع للإجابات اليومية.

### ب) نظام RAG
- قسّم كل ملف إلى مقاطع حسب العناوين (`##` / `###`).
- أضف وسماً: `audience=student|parent|teacher|admin|all`.
- لا تخلط أسراراً تقنية أو مفاتيح API في الفهرسة العامة.

### ج) موظفو المدرسة
- اطبع أو انشر `USER_GUIDE` و`TEACHER_GUIDE` و`SUPPORT` للتدريب.
- حدّث أرقام التواصل في `CONTACT.md` فقط دون تغيير باقي السياسات إلا بموافقة الإدارة.

## 5) قواعد ذهبية للمحتوى

1. **لا تخمّن أسعاراً** — استخدم دائماً: «يرجى التواصل مع الإدارة لمعرفة الأسعار الحالية.»
2. **لا تخترع ميزات غير مذكورة** في هذه القاعدة أو في إعداد المدرسة الفعلي.
3. **الخصوصية أولاً** — لا يطلب البوت كلمات مرور أو رموز تحقق كاملة في المحادثة.
4. **التحويل للدعم** عند الشك — راجع `SUPPORT.md` و`CONTACT.md`.
5. **اللغة** عربية فصحى مبسّطة، ودودة، واحترافية.

## 6) Placeholders يجب تعديلها قبل الإطلاق العام

ابحث عن القيم التالية واستبدلها:

| Placeholder | المعنى |
|-------------|--------|
| `{{SCHOOL_NAME}}` | اسم المدرسة الرسمي |
| `{{PLATFORM_URL}}` | رابط الموقع |
| `{{SUPPORT_EMAIL}}` | بريد الدعم |
| `{{SUPPORT_PHONE}}` | جوال الدعم |
| `{{SUPPORT_WHATSAPP}}` | واتساب الدعم |
| `{{SUPPORT_HOURS}}` | ساعات العمل |
| `{{CITY_COUNTRY}}` | المدينة / الدولة |
| `{{SCHOOL_ADDRESS}}` | العنوان إن لزم |

قيم افتراضية تقنية للمنصة (قابلة للتغيير من إعدادات المطور): راجع `CONTACT.md`.

عند إضافة ميزة جديدة للمنصة:

1. حدّث `PLATFORM_FEATURES.md`.

3. راجع `AI_AGENT_CONTEXT.md` حتى لا يجيب الوكيل بمعلومات قديمة.
4. سجّل تاريخ التحديث في أعلى الملف المعدَّل.

## 9) سيناريوهات استخدام القاعدة (أمثلة)

### مثال 1 — بوت واتساب لأولياء الأمور
ارفع `AI_AGENT_CONTEXT.md` كتعليمات، ثم فهرس `FAQ.md` و`SUPPORT.md` و`SUBSCRIPTIONS.md` و`CONTACT.md`. عندما يسأل ولي الأمر عن الرسوم يرد البوت: «يرجى التواصل مع الإدارة لمعرفة الأسعار الحالية» مع قنوات `CONTACT`.

### مثال 2 — تدريب المعلمين بداية العام
اطبع `TEACHER_GUIDE.md` و`PLATFORM_FEATURES.md`، وخصّص جلسة 45 دقيقة: الدخول، وضع أولمبياد مقابل أكاديمي، رفع واجب، إنشاء اختبار، استخدام المساعد الذكي بحذر.

### مثال 3 — يوم إطلاق للطلاب
وزّع ملخصاً من `USER_GUIDE.md` و`STUDENT_GUIDE.md`: كيف أسجّل الدخول، أين أرى النقاط، كيف أسلّم واجباً، ماذا أفعل إذا فشل الاختبار.

### مثال 4 — موظف استقبال المدرسة
يعتمد على `SUPPORT.md` للرد الهاتفي السريع، ويحوّل للدعم التقني فقط بعد استنفاذ الخطوات الأساسية.

### مثال 5 — نظام RAG داخلي
قسّم الملفات عند عناوين `##`، أضف metadata للدور والجمهور، وامنع فهرسة أي أسرار تشغيلية خارج هذا المجلد.

## 11) جودة المحتوى وصيانته

1. راجع القاعدة عند كل إصدار منصة كبير (`VERSION.md`).
2. سجّل تاريخ التعديل أعلى كل ملف معدَّل.
3. لا تحذف أقساماً يعتمد عليها البوت دون تحديث `AI_AGENT_CONTEXT.md`.
4. اختبر 10 أسئلة شائعة شهرياً على البوت وتأكد من عدم التخمين.
5. حافظ على العربية الفصحى المبسّطة وتجنب المصطلحات التقنية الثقيلة في ملفات المستخدم النهائي.

---

## 12) حدود هذه القاعدة

- لا تغني عن لوائح المدرسة الداخلية التأديبية.
- لا تغني عن استشارة قانونية للشروط والخصوصية قبل الاعتماد الرسمي.
- لا تتضمن مفاتيح API أو بيانات إنتاج حساسة.
- لا تصف أدوات مطور المنصة التفصيلية للمستخدم العام.

بهذا يصبح مجلد `knowledge-base/` حزمة جاهزة للرفع والتشغيل كقاعدة معرفة حقيقية لدعم أولمبياد النخبة.


## 13) قائمة تحقق قبل رفع القاعدة إلى Meta AI

1. استبدال جميع `{{PLACEHOLDERS}}` بقيم المدرسة الحقيقية.
2. التأكد أن جملة الأسعار موحّدة في الاشتراكات والأسئلة الشائعة.
3. رفع `AI_AGENT_CONTEXT.md` كتعليمات عليا غير قابلة للتجاوز.
4. تجربة عشرين سؤالاً من FAQ والتأكد من عدم اختراع ميزات.
5. ربط زر التحويل البشري بقنوات CONTACT.
6. مراجعة TERMS وPRIVACY من الإدارة قبل الإعلان العام.
7. تحديد مسؤول صيانة شهري للقاعدة.
8. الاحتفاظ بنسخة مؤرشفة بتاريخ اليوم داخل مستودع المدرسة.
9. منع فهرسة ملفات الكود أو مفاتيح التشغيل مع هذه الوثائق.
10. الإعلان للمعلمين أن البوت مساعد دعم وليس مصدراً للدرجات النهائية.

بعد إكمال القائمة تصبح القاعدة جاهزة للإنتاج التعليمي بأمان أعلى.
